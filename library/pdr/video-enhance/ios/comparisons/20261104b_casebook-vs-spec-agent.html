兩邊規則不同的 31 個The 31 where the rules differ

  • 依輸出 fps 計價（24 個）：Spec Agent 的 ECL 價目表依選的 fps 計價（例如 Professional 1080p：30 → 4、60 → 8、120 → 16 點／秒）；測試表規格只給 1080p Standard 30 fps = 2 點／秒，現在的列只檢查「扣點等於顯示價格」（Q-3、Q-4）。Price by output fps (24): the spec agent’s ECL rate table prices by the chosen fps (e.g. Professional 1080p: 30 → 4, 60 → 8, 120 → 16 credits/s); the casebook’s spec gives only 1080p Standard 30 fps = 2 credits/s, so its rows check only “charge = shown price” (Q-3, Q-4).
  • 2K 以上的影片（2 個）：Spec Agent 依 10/16 使用者需求在開啟面板前擋下；測試表依 Design 允許，只擋超過 4K（Q-13）。Sources of 2K and up (2): the spec agent blocks them before the panel opens, per the 10/16 user requirement; the casebook lets them in per the Design and blocks only sources over 4K (Q-13).
  • 時間軸刻度（5 個）：兩邊都引用 PM 9/29 ⑥，但讀法不同：Spec Agent 切換 Mode 會改刻度，測試表照 ⑥ 不改。需要 PM 決定。Strip scale (5): both quote PM 9/29 ⑥ but read it differently: the spec agent re-scales the strip when the Mode changes, the casebook keeps it, as ⑥ says. PM has to decide.

這些需要規格檔以外的資訊，暫不改列；拿到來源後記入需求表再改。These need information outside the spec files and are left for now; once there is a source, it goes in the request ledger and the rows change.

部分涵蓋與逐值涵蓋的 32 個The 32 covered in part or value by value

  • 設定組合（29 個）：Spec Agent 每種 Mode × 風格 × fps × 解析度組合各一個案例；測試表每個值實際生成一次（TC-219～224）並檢查存出的影片，因為規格沒有針對組合的規則。Setting combinations (29): the spec agent has a case per Mode × style × fps × resolution combination; the casebook generates with each value once (TC-219–224) and checks the saved video, since the spec gives no rule for combinations.
  • 部分涵蓋（3 個）：左把手往前拖時的預覽畫面（TC-216 只檢查上限）；播放頭往前拖與來回拖（TC-215 只往後拖，可拖範圍是 Q-21）。In part (3): the Preview while the left handle is dragged earlier (TC-216 checks only the stop); dragging the playhead earlier and back and forth (TC-215 drags it later only; how far it may go is Q-21).
